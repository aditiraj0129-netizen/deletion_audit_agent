## 3. Ablation - what each idea is worth (sample set)

| metric | full system | without worker_queue_accounts | without anonymized_attribution | without request_window | without snapshot_coverage | evidence-only baseline |
|---|---|---|---|---|---|---|
| status_accuracy | 100.0% | 100.0% | 100.0% | 100.0% | 96.9% | 96.9% |
| step_precision | 100.0% | 100.0% | 100.0% | 97.4% | 96.1% | 95.5% |
| step_recall | 98.4% | 89.6% | 94.8% | 98.4% | 88.6% | 77.7% |
| step_f1 | 99.2% | 94.5% | 97.3% | 97.9% | 92.2% | 85.7% |
| sequence_accuracy | 90.6% | 43.8% | 71.9% | 84.4% | 56.2% | 15.6% |
| resource_coverage | 98.4% | 89.6% | 94.8% | 98.4% | 91.7% | 79.3% |
| field_system_id_accuracy | 98.4% | 89.6% | 94.8% | 98.4% | 91.7% | 79.3% |
| field_operation_accuracy | 98.4% | 89.6% | 94.8% | 98.4% | 91.7% | 79.3% |
| field_state_accuracy | 98.4% | 89.6% | 94.8% | 98.4% | 91.7% | 79.3% |
| field_evidence_id_accuracy | 98.4% | 89.6% | 94.8% | 98.4% | 88.6% | 77.7% |

- *worker_queue_accounts*: many requests never show their account id next to an identifier; the id only exists in the deletion worker's queue. Without joint attribution those cases lose their account check.
- *anonymized_attribution*: an anonymised analytics profile has no identifier left by definition; it is tied to its request through the worker's learned schedule phase.
- *request_window*: observations from long before the request (a previous deletion of the same user) must not decide today's state.
- *snapshot_coverage*: an empty account snapshot only proves absence for people that snapshot covers.

## 4. Failures found and improvements made

| # | failure observed | fix |
|---|---|---|
| 1 | First pass linked every id on an OCR'd screenshot to every e-mail on it (a connector console showed two customers' flows). | Row-aware OCR: tesseract TSV on a 2x upscale, words grouped into visual rows; ids link to identifiers on their own row or the detail panel under them. |
| 2 | `reported_status` and worker `SUCCESS` were trusted in early drafts. | Status comes only from observed state at `audit_at`; activity rows are used for linking, never as proof. |
| 3 | Files captured after `audit_at` leaked into answers (e.g. a log exported two days later). | Evidence filter on manifest `captured_at <= audit_at`; observations can never be later than their file. |
| 4 | An empty account snapshot was read as 'every account is gone', flipping a still-present account to ABSENT. | Snapshot absence only counts when the snapshot covers the person (holds another of their records), or nothing else was ever seen for that record. |
| 5 | Whole-database SQL captures with no account rows gave no absence proof, so COMPLETE cases cited two different files. | A full capture (primary/replica JSON tables) now scopes every customer system, so the case's own file proves the account is gone. |
| 6 | A user deleted twice (March and September) got both account ids. | Observations must fall inside the request window (requested_at - 2 days ... audit_at). |
| 7 | Account ids only present in the worker queue were attributed greedily per case, so neighbouring requests stole each other's jobs. | Joint attribution over all known requests: reported_status <-> job result, learned schedule phase vs. the request's other jobs, and a lead-time prior. |
| 8 | Phase residues of pre-report and post-report jobs were mixed, making ~30 s-apart accounts indistinguishable. | Separate calibration for clean-up jobs (fixed minute slots, half-minute tick removed) and retries/checks. |
| 9 | A legacy contact-index hit (support replica) was treated as a support message to redact. | Contact-index / marketing contact lookups are SECONDARY_IDENTIFIER -> DELETE, matching rule_02. |
| 10 | Exports, tombstones and attachments shown only under an alias (statement number, file name, user key) were missed. | Catalog LINK_RESOURCE_IDENTITY aliases are searched in documents captured just before the catalog run. |
